换新电脑的兴奋通常在 30 分钟内消退。你打开终端、启动 Claude Desktop、输入第一个问题——然后发现，它完全不认识你。

你在旧 Mac 上花了三个月"调教"好的 AI——你的代码风格偏好、项目的命名规范、每周五下午的复盘模板——全部归零。AI 又变成了出厂设置。

这个痛点，2026 年有了系统级的解决方案：**Agent 灵魂资产备份**。

## 传统方案为什么不行

大多数人的"同步"方法是这样的：

- 把 `~/.claude` 或 `~/.hermes` 目录打包拷贝
- 手动导出 Prompt 模板
- 在新电脑上重写一遍 .cursorrules

这有三个致命缺陷：

- **不跨框架**：Claude 和 Hermes 的配置格式不同，手拷目录经常漏掉记忆库和密钥脱敏配置
- **不完整**：你只能拷贝配置文件，无法带走"AI 在对话中积累的偏好"
- **不可靠**：对话流水账（state.db）拷过去也没用，真正有价值的是调教产物，而不是流水账本身

## Moltable 的灵魂资产备份方案

核心思路：把你调教出来的资产——而不是对话流水账——打包成版本化的备份。任何框架实例都能从同一个备份源还原。

### 备份什么、排除什么

**备份**：SOUL.md、AGENTS.md、USER.md、config.yaml（MCP 配置，密钥脱敏）、memories/、skills/。

**自动排除**：对话流水账（state.db / WAL / FTS）和密钥（.env / *.key）——流水账占空间且无调教价值，密钥不该进云端。

## 跨平台实战：Mac → Windows → Linux

一个真实工作流：

- **办公室 Mac**：Hermes，白天积累代码审查偏好，收工前 `moltable backup push`
- **回家 Windows 台式机**：Claude，`moltable backup pull` 直接继承白天的调教成果
- **服务器 Linux**：OpenClaw 跑自动化任务，从同一个备份源 `pull`

三台设备、多个框架实例，各自的调教成果都有版本历史，任何一台出问题都能完整还原。这不再是科幻。

## 高级技巧

- **多备份源管理**：每台设备、每个框架实例一个独立备份源，`sources` 随时查看，互不覆盖
