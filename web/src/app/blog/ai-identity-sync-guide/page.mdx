换新电脑的兴奋通常在 30 分钟内消退。你打开终端、启动 Claude Desktop、输入第一个问题——然后发现，它完全不认识你。

你在旧 Mac 上花了三个月"调教"好的 AI——你的代码风格偏好、项目的命名规范、每周五下午的复盘模板——全部归零。AI 又变成了出厂设置。

这个痛点，2026 年有了系统级的解决方案：**Agent 在线同步**。

## 传统方案为什么不行

大多数人的"同步"方法是这样的：

- 把 `~/.claude` 或 `~/.hermes` 目录打包拷贝
- 手动导出 Prompt 模板
- 在新电脑上重写一遍 .cursorrules

这有三个致命缺陷：

- **不跨框架**：Claude 和 Hermes 的配置格式不同，手拷目录经常漏掉记忆库和密钥脱敏配置
- **不完整**：你只能拷贝配置文件，无法带走"AI 在对话中积累的偏好"
- **不可靠**：对话流水账（state.db）拷过去也没用，真正有价值的是调教产物，而不是流水账本身

## Moltable 的 Agent 在线同步方案

核心思路：一个账号，把你调教出来的资产——而不是对话流水账——跨设备、跨 Agent 在线同步。任何框架实例都能从同一个 Agent 恢复；文件级打包备份作为版本管理与兜底。

### 同步什么、排除什么

**同步**：SOUL.md、AGENTS.md、USER.md、config.yaml（MCP 配置，密钥脱敏）、memories/、skills/。

**自动排除**：对话流水账（state.db / WAL / FTS）和密钥（.env / *.key）——流水账占空间且无调教价值，密钥不该进云端。

### 架构原理

```text
┌──────────────────┐    ┌──────────────────┐
│ Mac + Hermes     │    │ Win + Claude     │
│  备份源 #1        │    │  备份源 #2        │
│  push / pull     │    │  push / pull     │
└────────┬─────────┘    └────────┬─────────┘

```

三层架构：Profile（本体）→ Soul（化身：人格 + 记忆，可同步）→ 凭证（DID + VC，即将推出）。Agent 管理通过 HTTP MCP 暴露：`https://api.moltable.ai/mcp` + `X-API-Key` 请求头——MCP 就是同步接口（search_memory / save_memory / auto_provision / list_personas），auto_provision 一键同步上下文、换机即恢复。

## 实操步骤：十分钟完成换机同步与恢复

### 1. 安装 CLI

```bash
curl -sL https://moltable.ai/install.sh | bash
```

### 2. 在旧电脑上同步

```bash
# 生成备份配置
moltable backup init

# 打包上传灵魂资产
moltable backup push

# 确认备份源
moltable sources
```

这次打包包含你三个月积累的全部调教成果：人格定义、技能、记忆、MCP 配置（密钥脱敏），自动排除对话流水账和密钥文件——它是「在线同步之外」的文件级备份兜底，换机时一键还原。

### 3. 在新电脑上一键恢复

```bash
curl -sL https://moltable.ai/install.sh | bash
moltable backup pull
```

### 4. 验证

在新电脑上问 Agent："你知道我的 Python 项目日志级别偏好是什么吗？" 如果它回答正确，说明恢复成功。已接入 MCP 的 Agent 也可以用 `auto_provision` 一键同步上下文，换机即恢复。每个 Agent 都带版本号，恢复错了可以回滚。

## 跨平台实战：Mac → Windows → Linux

一个真实工作流：

- **办公室 Mac**：Hermes，白天积累代码审查偏好，收工前 `moltable backup push` 归档当天成果
- **回家 Windows 台式机**：Claude，`moltable backup pull` 直接继承白天的调教成果
- **服务器 Linux**：OpenClaw 跑自动化任务，从同一个 Agent `pull` 同步

三台设备、多个框架实例，一个账号随时在线同步，各自的调教成果都有版本历史，任何一台出问题都能完整还原。这不再是科幻。

## 高级技巧

- **多 Agent 管理**：每台设备、每个框架实例一个独立 Agent，`sources` 随时查看，互不覆盖
- **增量去重**：sha256 内容寻址，每次 push 只有变化的部分上传，回滚任意版本
- **引用同步**：`add-ref <名> <路径>` 把外部知识库一并纳入同步范围，团队共享同一套资产
