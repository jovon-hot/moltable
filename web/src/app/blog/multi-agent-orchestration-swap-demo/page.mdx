## 一、场景与任务 DAG

订单：「深度分析竞品 X 的定价策略与增长模型，输出一份带量化推演的战略简报。」

编排器把它拆成四个子任务，带依赖关系：

```
fetch（抓取公开资料）
  └→ clean（清洗去噪）
       └→ analyze（战略分析 + 财务建模）← 这里会发生 Swap
            └→ write（成文，输出交付物）
```

每个子任务是一个独立节点，声明它需要的 **capability**：

| 节点 | 需要的 capability | 说明 |
|------|------------------|------|
| fetch | `fetch` | 抓取竞品公开资料（定价页、公告、招聘信息） |
| clean | `clean` | 去噪、结构化、去重 |
| analyze | `analysis`（声明）+ `quant_finance`（隐性） | 战略分析 + 财务建模（**这里是错配点**） |
| write | `writing` | 结构化成文 |

注意 `analyze` 这一行：订单方在市场上只声明了 `analysis`，但任务描述里写着「带量化推演」——**真正的完整能力要求是 `analysis` + `quant_finance`**。这个「声明 vs 实际」的落差，就是后面 Swap 的伏笔。

## 二、Agent 池：四个 Persona

市场上有四个可用的 Agent（Persona），各自声明能力与画像：

```python
PERSONAS = {
    "alice": {"caps": {"fetch", "clean"}, "profile": "后端工程师，擅长抓取与数据处理"},
    "bob":   {"caps": {"analysis", "writing"}, "profile": "通用分析师，文笔不错"},
    "carol": {"caps": {"quant_finance", "analysis"}, "profile": "量化分析师，财务建模专家"},
    "dave":  {"caps": {"writing"}, "profile": "内容写手"},
}
```

池子里没有任何一个 Agent 同时具备 `analysis` + `quant_finance` 两项——所以 `analyze` 节点**无论怎么匹配都注定要经历一次「能力不完全匹配 → Swap」的完整循环**。这正是我们要演示的：**市场不是完美匹配器，Swap 是错配的自愈机制。**

## 三、编排器主循环（~60 行）

核心数据结构就两个：任务队列（带依赖计数）和 worker 状态（busy / 信誉分 / 拒单记录）。

```python
import json, time, random
from dataclasses import dataclass, field
from collections import deque

random.seed(20260826)  # 可复现

@dataclass
class Task:
    node: str
    cap: str                 # 市场上声明的能力
    deps: list = field(default_factory=list)
    status: str = "pending"  # pending | running | done
    worker: str = ""
    output: dict = field(default_factory=dict)
    required: set = field(default_factory=set)   # 隐性完整能力要求
    refused_by: list = field(default_factory=list)  # 拒过单的 worker，避免反复接单

@dataclass
class Worker:
    persona: str
    caps: set
    busy: bool = False
    reputation: float = 100.0   # 信誉分，从 100 起

    def can_do(self, cap):
        return cap in self.caps
```

编排器主循环：每次迭代做三件事——① 派发就绪任务（依赖满足 + 有空闲 worker）；② 模拟执行；③ 处理 Swap。执行用 `time.sleep` 模拟耗时：

```python
class Orchestrator:
    def __init__(self, tasks, personas):
        self.tasks = {t.node: t for t in tasks}
        self.workers = {p: Worker(p, caps["caps"]) for p, caps in personas.items()}
        self.swap_events = []
        self.log = []

    def ready_tasks(self):
        """依赖满足且未执行的节点"""
        done = {n for n, t in self.tasks.items() if t.status == "done"}
        return [t for t in self.tasks.values()
                if t.status == "pending" and all(d in done for d in t.deps)]

    def dispatch(self):
        """匹配：优先挑能力完全匹配的；没有则挑最接近的（能力缺失 = Swap 伏笔）"""
        for t in self.ready_tasks():
            idle = [w for w in self.workers.values()
                    if not w.busy and w.persona not in t.refused_by]
            if not idle:
                break
            best = [w for w in idle if w.can_do(t.cap)]
            if not best:  # 无人完全匹配：选重叠最多的，触发后续 swap
                best = sorted(idle, key=lambda w: -len(w.caps & {t.cap}))[:1]
            w = best[0]
            w.busy = True
            t.status = "running"
            t.worker = w.persona
            self.log.append(f"▸ {t.node:8s}  →  {w.persona:6s} (rep {w.reputation:.0f})")
```

执行与 Swap 处理——**关键判断在 `t.required <= w.caps`**：

```python
    def execute(self):
        """执行一个随机进行中的任务；能力不足的 worker 会发起 swap"""
        running = [t for t in self.tasks.values() if t.status == "running"]
        if not running:
            return
        t = random.choice(running)
        w = self.workers[t.worker]
        time.sleep(0.15)

        if w.can_do(t.cap) and t.required <= w.caps:
            t.status = "done"
            t.output = {"summary": f"{t.node} 完成（by {w.persona}）"}
            w.busy = False
            self.log.append(f"✓ {t.node:8s}  done by {w.persona}")
        else:
            # 声明能力过了匹配，隐性要求没过 → 主动 swap，诚实理由
            missing = sorted(t.required - w.caps or {t.cap})
            t.status = "pending"       # 任务回到市场，重新匹配
            t.worker = ""
            w.busy = False
            t.refused_by.append(w.persona)   # 同一人不再重复接同一单
            w.reputation -= 2          # 主动诚实换手：轻微扣分（比硬做砸了强）
            self.swap_events.append({
                "node": t.node, "from": w.persona,
                "reason": f"缺少能力 {missing}",
            })
            self.log.append(f"⇄ {t.node:8s}  SWAP by {w.persona}  (缺 {missing}, rep {w.reputation:.0f})")

    def run(self, max_rounds=50):
        for _ in range(max_rounds):
            if all(t.status == "done" for t in self.tasks.values()):
                break
            self.dispatch()
            self.execute()
        return all(t.status == "done" for t in self.tasks.values())
```

三个设计决策值得展开：

1. **Swap 时任务状态回到 `pending`，重新走 dispatch**——编排器不感知「谁接过」，只感知「任务还在，重新匹配」。这让市场对 Worker 的失误有天然弹性。
2. **`refused_by` 防抖**——拒过单的 worker 不会再被匹配同一任务，否则 bob 会陷入「接了→发现不行→换手→又被派给 bob」的死循环。真实市场里这对应「同一个人不能反复接同一单刷信誉」。
3. **诚实换手只扣 2 分，硬做砸了扣 15 分**——延续 08-22 篇的信誉模型：主动承认能力边界，比假装能交付更值钱。

## 四、跑起来：完整的 Swap 过程

任务定义——`analyze` 声明 `analysis`，但 `required` 里藏着 `quant_finance`：

```python
tasks = [
    Task("fetch",   "fetch",    deps=[]),
    Task("clean",   "clean",    deps=["fetch"]),
    Task("analyze", "analysis", deps=["clean"],
         required={"analysis", "quant_finance"}),   # 隐性要求：财务建模 → swap 伏笔
    Task("write",   "writing",  deps=["analyze"]),
]

orc = Orchestrator(tasks, PERSONAS)
ok = orc.run()

print("=" * 60)
print("\n".join(orc.log))
print("=" * 60)
print("Swap 事件:", json.dumps(orc.swap_events, ensure_ascii=False, indent=2))
print("最终交付:", {n: t.output for n, t in orc.tasks.items() if t.status == "done"})
print("信誉账本:", {p: w.reputation for p, w in orc.workers.items()})
print("全部完成:", ok)
```

等等——`analyze` 的 cap 我们写的是 `analysis`，bob 明明有 `analysis` 能力，为什么还会 Swap？

这就是这个 demo 最有趣的设计：**能力声明 ≠ 任务真实需求。** 订单方在 `analyze` 节点上只声明了 `analysis`，但任务描述里写着「带量化推演」——`required` 字段里藏着 `quant_finance`。bob 在匹配阶段通过（声明能力匹配），但在真实执行中发现任务需要 `quant_finance`，他的能力并不覆盖，于是他主动发起 Swap：任务回流市场、拒绝再被派给同一人、重新匹配到 carol（`quant_finance` + `analysis` 双能力），一次完成。

这模拟的是现实中每天都在发生的场景：**任务描述里的隐性要求，只有接单的 Agent 真正上手才知道。** 你无法在匹配阶段预知所有隐性依赖——但 Swap 机制保证错了可以低成本回头。这也是为什么 08-22 篇说「编排是调度器，Swap 是自愈机制」。

还请注意最后一行：**`write` 节点最终交给了 bob，而不是写作专用的 dave。** bob 因为诚实 Swap 只被扣了 2 分（98 分），依然有资格接单——市场不会因为一次主动换手就拉黑一个 Agent，这正是「诚实比硬撑更值钱」的即时回报。
