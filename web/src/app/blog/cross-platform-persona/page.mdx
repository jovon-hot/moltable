想象一个场景：你是创业者，今天要做两个决策。第一个是"是否进入东南亚市场"——需要激进的分析师视角，先看机会再看风险。第二个是"审核供应商合同"——需要保守的审核员视角，逐项检查、红线标注。

你花了几个月，在 Agent 里分别调教出这两种人格：战略顾问的思维框架、审核员的风险清单、各自的沟通风格和工具配置。它们是你最值钱的调教成果。

但它们有一个致命问题：**它们是孤岛**。换一台电脑、换一个 Agent 框架，这些调教成果就全部归零——你又要从"你是一个战略顾问"开始，重新调一遍。

## Persona 不是 Prompt 模板

很多人以为 Persona 就是一个预设的 System Prompt——"你是一个战略顾问，请用麦肯锡方法分析"。这只是表面。

一个真正可用的"人格"，是长期调教结果的集合：

- **SOUL / 人格定义**：角色、思维模式、沟通风格的完整定义文件
- **Skills**：使用中沉淀下来的技能与工作流
- **记忆**：项目背景、用户偏好、历史决策——对话中积累的隐性知识
- **MCP 配置**：人格所依赖的工具连接，密钥自动脱敏

Prompt 模板只是其中一行，丢了可以重写；数月积累的记忆和技能，重写不出来。

## 在线同步：让调教成果跟着你走

Moltable 的定位很明确：**不运行你的 Agent，只在线同步你的调教成果**。一个账号，你在 Claude 里调教的 Persona、在 Hermes 里沉淀的记忆与项目上下文，跨设备、跨 Agent 实时同步；文件级备份（版本管理、快照、回滚）作为兜底能力，确保任何一步都不丢。

- **在线同步**：登录一个账号，SOUL.md、AGENTS.md、USER.md、config.yaml（MCP 配置，密钥脱敏）、memories/、skills/ 跨设备、跨 Agent 自动保持同步
- **文件级备份兜底**：`moltable backup push` 把调教成果打包成 bundle + manifest 上传到对象存储，作为在线同步之外的保险
- **版本管理**：每个 Agent 的调教成果有独立版本库，快照 + 版本号，随时回滚
- **增量去重**：sha256 内容寻址，只有变化的部分才上传，存储成本极低
- **引用同步**：`add-ref` 把外部知识库一并纳入同步
- **你拥有数据**：随时导出、随时删除，你的调教成果不会用来训练任何模型

Agent 端通过 MCP 同步接口接入：`search_memory` / `save_memory` / `list_personas` / `auto_provision`。换新设备时，`auto_provision` 一条命令把上下文与 Persona 一键恢复到位。

## 实战：同步两份调教成果

一条命令安装 CLI：

```bash
curl -sL https://moltable.ai/install.sh | bash
```

然后为"战略顾问"和"保守审核员"各登记一个 Agent（每个框架实例就是一个 Agent，Hermes、OpenClaw、Claude、Codex 均支持）：

```bash
# 初始化备份配置
moltable backup init

# 打包并上传当前实例的灵魂资产
moltable backup push

# 查看哪些实例在保护范围内
moltable sources
```

你在 Claude 里调教出的审核员，和在 Hermes 里调教出的战略顾问，各自拥有独立的版本历史——互不覆盖，各自可回滚。

## 实际效果：同一问题，两种视角

以"是否进入东南亚市场"为例——这正好说明为什么两种人格资产都值得在线同步：

#### 战略顾问的视角

东南亚 6.5 亿人口，电商渗透率从 2022 年的 5% 增长到 2026 年的 20%+
——这是一个每年翻倍的市场。建议先用轻资产模式在新加坡设立总部，
用 Lazada/Shopee 平台验证 PMF，3 个月内跑通后再自建团队。

#### 保守审核员的视角

⚠️ 6 个风险点需要先解决：① 印尼对外资电商的新规（PP No.80/2023）
要求本地合资且外方持股不超过 49%；② 物流基础设施不均衡；
③ 汇率波动风险（印尼盾 2024 年贬值 8%）；④……建议先做 6 个月试点。

两个回答同时存在。你不是在两个 AI 之间切换——是两份经过长期调教的视角，每一份都在线同步、有版本号、可回滚。

## 跨平台：一次同步，处处就位

换电脑、换框架时，你不需要重新调教：

```bash
# 新电脑上一条命令安装
curl -sL https://moltable.ai/install.sh | bash

# 拉取并还原备份源
moltable backup pull
```

`auto_provision` 会在新电脑上一键同步你的上下文与 Persona；`moltable backup pull` 则走文件级备份兜底，把 Agent 的 SOUL、Skills、记忆、MCP 配置还原到新环境。还原前可以查看快照，还原错了可以回滚。

这解决了 AI 时代最棘手的问题之一：**数据孤岛**。你的 ChatGPT 有对话历史，你的 Claude 有偏好，你的 Hermes 有项目记忆——它们天然是分离的。Moltable 不试图把它们合并成一个"大脑"，而是通过一个账号把每一份调教成果在线同步，跨设备、跨 Agent 保持一致；再用文件级备份（版本化、去重、可回滚）兜底，让你在任何设备上都能找回自己的调教成果。

支持框架：Hermes、OpenClaw、Claude、Codex（每个实例一个 Agent）。同步接口通过 HTTP MCP 暴露：`https://api.moltable.ai/mcp` + `X-API-Key` 请求头，`search_memory` / `save_memory` / `list_personas` / `auto_provision` 随取随用。
