**谈到「Agent 记忆」，Letta 和 Moltable 都被摆上过同一张对比表。但如果你真的把两者放进生产，会发现它们回答的是两个完全不同的问题：Letta 给 Agent 一个会自我编辑的工作记忆，Moltable 让你的身份、记忆、Persona 跨设备、跨 Agent 在线同步（换机 auto_provision 一键恢复）。前者是 Agent 的内部状态机，后者是你的在线同步层。**

> **English summary**: Letta (f.k.a. MemGPT) and Moltable both claim the "memory" label, but they solve different problems. Letta runs *stateful agents* whose context window is organized into self-editing **memory blocks** — the agent rewrites its own memory to stay consistent. Moltable doesn't run your agent at all: it **keeps your agent's soul in sync** (SOUL, Skills, MCP configs, memories) across devices and agents, with versioned, portable, cross-framework-migratable file-level snapshots as insurance. One is the agent's internal memory state machine; the other is your online sync layer. They are complementary, not competing.

这是竞品矩阵的最后一篇。此前我们对比过 [mem0](https://www.moltable.ai/blog/moltable-vs-mem0-identity-vs-memory)、[Zep](https://www.moltable.ai/blog/moltable-vs-zep-temporal-memory)，也发过 [2026 Agent 记忆全景盘点](https://www.moltable.ai/blog/agent-memory-landscape-2026)。Letta 是那个最「像 Moltable」、也最容易被误读为直接竞品的玩家——因为它是唯一一个把「身份」「人格」这些词写进产品里的开源记忆框架。所以这篇要把话说透：**像在哪，根本不像在哪。**

先给结论：**如果你在构建一个需要长期自我进化的 Agent 运行时，选 Letta；如果你已经用着 Hermes / OpenClaw / Claude / Codex / Cursor 这些 Agent、不想再换框架、只想让调教成果在线同步、走到哪跟到哪，选 Moltable。两者不冲突，可以一起用。**

## 为什么它们都被叫「记忆」，却不是一回事

「记忆」这个词被用滥了。一个向量库叫记忆，一个 RAG 管线叫记忆，一个在线同步系统也叫记忆。但拆开看，市面上的「Agent 记忆」其实分三件事：

1. **运行时上下文管理**：对话进行中，Agent 当前「看到」什么、记住什么。
2. **持久化记忆存储**：对话结束后，哪些事实被沉淀下来供下次检索。
3. **资产的在线同步与迁移**：你调教的整套 Agent（技能、人格、配置、记忆）怎么不丢、怎么跟着你走。

mem0 和 Zep 主要做第 2 件。**Letta 是第 1 件的极致**——它把「Agent 怎么管理自己的上下文」做成了操作系统。**Moltable 是第 3 件的唯一玩家**——它根本不运行你的 Agent，只负责把你调教出来的「灵魂」跨设备、跨 Agent 在线同步，并提供版本化文件级备份与跨框架迁移。

把「管理 Agent 内部状态」和「同步你的外部资产」放在同一张对比表里比优劣，本身就是个伪命题。它们应该在同一份技术栈里，而不是同一张 PK 表里。

## Round 1: Letta 的记忆状态机

Letta 的前身是 MemGPT（arXiv 2310.08560，*MemGPT: Towards LLMs as Operating Systems*）。这篇论文的洞见非常漂亮：**把 LLM 的上下文窗口当作操作系统的虚拟内存**，让模型自己决定什么「换进」上下文、什么「换出」到外部存储——就像操作系统在主存和磁盘之间做分页。

落到产品上，就是三个关键设计：

### 1. Memory blocks：自编辑记忆

Letta 把上下文窗口拆成若干有名字、有大小上限的 **memory block**——典型的是 `human`（关于用户的事实、偏好）和 `persona`（Agent 的自我认知、人格、行为准则）。关键不在「分块」，而在**块是 Agent 自己编辑的**：

```python
# Letta 的「反思记忆」工具——Agent 重写自己的某个 memory block
def rethink_memory(agent_state, new_memory: str, target_block_label: str):
    if agent_state.memory.get_block(target_block_label) is None:
        agent_state.memory.create_block(label=target_block_label, value=new_memory)
    agent_state.memory.update_block_value(label=target_block_label, value=new_memory)
```

用户说了一句「我不喜欢香草冰淇淋」，Agent 把它写进 `persona` block，从此保持一致。这就是 **self-editing memory（自编辑记忆）**——记忆不是被动堆积，而是 Agent 主动维护、随时改写的一份「自我状态」。

### 2. MemFS：git 版的记忆文件系统

Letta Code（当前的活跃代码库）把记忆进一步落成了 **MemFS——一个 git-backed 的记忆文件系统**。记忆以文件形式组织、用 git 版本化，Agent 可以 inspect、edit、commit。配套的命令很说明问题：`/remember`（显式教它一条）、`/doctor`（审计记忆的冗余/重复/token 占用）、`/sleeptime`（配置后台整理）。

### 3. Dreaming：睡眠时间计算

Letta 最超前的一招是 **dreaming（睡眠时间计算，来自其 sleep-time compute 研究）**：Agent 在空闲时派后台子 Agent 回看历史对话、沉淀经验、更新 memory block，而不打断你的正常工作。这跟 Cursor 的后台 agent 是同一类思路，但用在「记忆的自我整理」上。

**小结：Letta 是一台「状态机」——一个会持续重写自身状态、并让这种状态跨对话存续的 Agent 运行时。** 它的记忆是「活」的，活在 Agent 的上下文窗口里，由 Agent 自己掌控。

## Round 2: Moltable 的 Agent 在线同步层

Moltable 走的是另一条路。它**不运行你的 Agent**——你继续用你的 Hermes、OpenClaw、Claude、Codex、Cursor，Moltable 只做一件事：让你调教出来的整套「灵魂资产」跨设备、跨 Agent 在线同步——一个账号，走到哪跟到哪；同时提供文件级备份（版本化快照、回滚）作为兜底。

### 同步的原子单位是「灵魂」，不是「对话」

```
curl -sL https://moltable.ai/install.sh | bash   # 一行安装
moltable backup push                       # 打包上传你的 Agent 灵魂资产
moltable backup pull                       # 换机/换框架后还原
```

文件级备份的内容是 SOUL（人格 + 记忆）、Skills、MCP 配置、以及你引用的知识库——**自动排除对话流水账**。这个「只备份灵魂、不备份流水账」的取舍很关键：实测一个调教成熟的 Agent，灵魂 39MB，而对话日志 1.2GB，压缩比 30 倍。你备份的是「你是谁」，不是「你昨天聊了 800 条天」。

同步则走 MCP 接口：`search_memory` / `save_memory` 让 Agent 实时读写你的记忆，`auto_provision` 在新设备上一键同步完整上下文——配合文件级备份，双保险。

### 三层架构：Profile → Soul → 凭证

- **Profile（本体）**：客观事实，不可复制。
- **Soul（化身）**：人格 + 记忆，在线同步，跨框架迁移即将推出。
- **凭证（身份证明）**：DID+VC，给灵魂签出处（即将推出）——这个灵魂是谁调的、是不是正版、授权给谁，密码学可验证。

### 版本管理 + 跨框架迁移

每个 Agent 都有独立的文件级版本库（快照 + 版本号），改坏了随时回滚到任意历史版本。而**跨框架迁移**是 Moltable 最独特的承诺：用你自己的 LLM，把一份 Hermes 灵魂翻译成 OpenClaw / Claude / Codex 版本——这是「在线同步」之上的「迁移」，是 Moltable 与所有记忆产品的根本分界线。

**小结：Moltable 是一条「同步层」——它不管你的 Agent 怎么运行、怎么记忆，它只保证你花了几百小时调教出来的那个「你」永远在线、永远带得走。**

## Round 3: 架构哲学——运行时 vs 同步层

这是两者最深的分野，值得单独说。

**Letta 是一座「活的房子」。** 你的 Agent 住进去，房子自己会打扫（dreaming）、会重新装修（self-editing memory）、会记日记（MemFS）。但代价是——你得搬进去住。Agent 必须构建在 Letta 的运行时上，记忆也锁在这个框架里。

**Moltable 是一条「同步层」。** 你不住在里面。你继续住在 Hermes、Claude、Cursor 这些「房子」里，同步层负责让你在每间房子里调教出来的灵魂资产跨设备、跨 Agent 在线同步，同时收好、编号，随时能搬到下一间房子——甚至搬到另一种「房型」（框架）。

「运行时」和「同步层」不是竞争关系，是上下游关系。一个 Letta Agent 的 SOUL、Skills、MemFS 快照，本身就是一份可以交给 Moltable 在线同步的「灵魂资产」。**最优解不是二选一，而是让 Moltable 同步你的 Letta Agent。**

**Moltable**：**Free $0**（3 个 Agent · 100MB · 始终免费）；**Pro $3/月**（10 个 Agent · 1GB · 引用同步 · 跨框架迁移即将推出）；**Ultra $5/月**（100 个 Agent · 10GB）。MIT 开源，自托管免费。

一个是「给 Agent 租个脑子」的月费，一个是「让灵魂永远在线」的月费。用途不同，很难直接比价；但如果你的痛点是「调教成果会丢、换设备全没」，$3/月 和 $20/月 的分量其实差得很远。

## Round 5: 什么时候用哪个

**选 Letta，当你要：**
- 从头构建一个需要长期自我进化的 Agent（记忆会自我整理、自我纠偏）
- 认同「Agent 应该像操作系统一样管理自己的上下文」这套哲学
- 在 Letta 的运行时上做产品，接受把 Agent 绑定在这个框架里
- 想要开箱即用的 memory blocks + dreaming，而不想自己搭记忆管线

**选 Moltable，当你要：**
- 继续用 Hermes / OpenClaw / Claude / Codex / Cursor，不想换框架
- 花了大量时间调教 Agent，担心换机器、换框架就全丢
- 想把调教成果版本化、可回滚、可跨框架迁移
- 文件级备份只打包灵魂不打包流水账（30 倍压缩），数据 100% 归你、MIT 开源
- 未来需要 DID+VC 给灵魂签出处

**以及——两个都要：** 用 Letta 构建你的 Agent，用 Moltable 同步你的 Letta Agent 的灵魂资产。它们在同一份技术栈里各司其职。

## 结论

把 Letta 和 Moltable 当作竞品，是「记忆」这个标签制造的最大误会。Letta 是一台记忆状态机——它让 Agent 的记忆活起来、会自我进化；Moltable 是一条在线同步层——它让你的调教成果永远在线、永远带得走。一个管 Agent 的「脑子」，一个管你的「遗产」。

竞品矩阵到此收齐：mem0 做记忆层、Zep 做知识图谱、Letta 做状态机、Moltable 做在线同步层。**这场「Agent 记忆」的竞赛，真正的分野不是谁存得多，而是谁回答了「我的调教成果凭什么不丢、凭什么跟着我走」这个问题——在这个问题上，Moltable 是唯一的答案。**
