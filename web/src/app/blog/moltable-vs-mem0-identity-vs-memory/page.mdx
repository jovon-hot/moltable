**你的 AI Agent 已经「记住」了很多东西——它知道你用 TypeScript、你部署到 Railway、你喜欢 tab 缩进。但你换一台电脑，它还是不认识你。**

这就是 Memory Layer 和 Identity Layer 的核心差异。而大多数开发者还没意识到这两个概念的区别。

mem0（62K+ GitHub Stars）是目前最成功的 AI Memory OSS 项目。Moltable 则选择了不同的路径——不做 Memory Layer，做 Identity Layer。这两者有什么区别？什么时候该用哪个？本文给你答案。

---

## Memory Layer 做了什么

mem0 的核心能力：**在 Agent 对话中自动提取、存储、检索记忆。**

```
用户: "我最近在重构 auth 模块，用 JWT 替代 session"
mem0: → 提取事实 "user is refactoring auth module, using JWT"
       → 存储到向量数据库
       → 下次对话自动关联这条记忆
```

它的架构是：

- **输入层**：监听 Agent 对话流
- **提取层**：LLM 从对话中提取结构化记忆
- **存储层**：向量数据库存储记忆嵌入
- **检索层**：查询时返回最相关的 top-k 记忆

**mem0 擅长什么：**
- 记住你的技术栈、偏好、项目上下文
- 自动去重和记忆衰减
- 开箱即用，Python + TypeScript SDK

**mem0 不擅长什么：**
- 跨 Agent 平台共享身份（Claude → Cursor → Codex）
- 角色切换（"工作模式" ↔ "创作模式"）
- 换电脑、重装系统后恢复环境

## Identity Layer 做了什么

Moltable 的核心理念：**Memory 是手段，Identity 是目的。**

```
身份同步:
  Agent A (Claude)    → 读取 Persona「全栈开发者」
  Agent B (Cursor)    → 读取同一个 Persona
  Agent C (Codex)     → 读取同一个 Persona
  
  换电脑？→ 同步码恢复身份 → 3 分钟全部回来
```

Moltable 的架构是：

- **Identity 层**：跨平台唯一标识
- **Persona 层**：角色管理（开发者/架构师/写作者）
- **Sync 层**：同步码 + Agent Invite 机制
- **Memory 层**：记忆卡片 + 搜索
- **Project 层**：项目地图 + 上下文

**Moltable 擅长什么：**
- 一条命令接入 Claude / Cursor / Codex / OpenCode
- 角色切换——一个账号多个 Persona
- 换电脑一键恢复——同步码机制
- 开源、MIT 协议

## 什么时候用哪个？

**用 mem0 的场景：**
- 你只在 **一个 Agent 平台** 工作
- 你需要 **开箱即用** 的 Python SDK
- 你要做 **记忆密集** 的长时间 Agent 对话
- 你在做 Agent 研究或实验

**用 Moltable 的场景：**
- 你在 **多个 Agent 平台** 之间切换（Claude + Cursor + Codex）
- 你经常 **换电脑、重装系统**
- 你需要 **角色切换**（开发 vs 写方案 vs 设计）
- 你想要一个 **开源、MIT 协议** 的身份基础设施
- 你重视 **数据所有权**——身份数据归你

**它们不是替代关系。mem0 是最优秀的 Memory Layer，Moltable 是在它之上构建 Identity Layer。**

最佳实践：**mem0 存记忆，Moltable 管身份。** 两者可以同时使用——Agent 通过 MCP 协议同时接入两个服务，一个负责「记住对话」，一个负责「记住你是谁」。
