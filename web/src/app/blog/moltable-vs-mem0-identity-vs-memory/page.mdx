**你的 AI Agent 已经「记住」了很多东西——它知道你用 TypeScript、你部署到 Railway、你喜欢 tab 缩进。但你换一台电脑，它还是不认识你。更糟的是：你花几个月调教出来的 SOUL、Skills、MCP 配置，可能随硬盘一起消失。**

mem0（62K+ GitHub Stars）是目前最成功的 AI Memory OSS 项目。Moltable 则选择了不同的路径——不做 Memory Layer，做灵魂资产备份仓库。这两者有什么区别？什么时候该用哪个？本文给你答案。

## Memory Layer 做了什么

mem0 的核心能力：**在 Agent 对话中自动提取、存储、检索记忆。**

```
用户: "我最近在重构 auth 模块，用 JWT 替代 session"
mem0: → 提取事实 "user is refactoring auth module, using JWT"
       → 存储到向量数据库
       → 下次对话自动关联这条记忆
```

它的架构是：

- **输入层**：监听 Agent 对话流
- **提取层**：LLM 从对话中提取结构化记忆
- **存储层**：向量数据库存储记忆嵌入
- **检索层**：查询时返回最相关的 top-k 记忆

**mem0 擅长什么：**
- 记住你的技术栈、偏好、项目上下文
- 自动去重和记忆衰减
- 开箱即用，Python + TypeScript SDK

**mem0 不擅长什么：**
- 跨 Agent 平台迁移（Claude → Cursor → Codex 之间没有桥梁）
- 跨工具的工作模式切换（"工作模式" ↔ "创作模式"）
- 换电脑、重装系统后恢复环境

## 灵魂资产备份仓库做了什么

Moltable 的核心理念：**记忆是运行时的东西，调教成果是需要版本化的资产。**

mem0 解决「Agent 记住了什么」；Moltable 解决「你调教出来的东西会不会丢」。Moltable 不运行你的 Agent——它是「保险箱」，不是记忆层、也不是状态机。它把你调教 AI 的成果打包成版本化、去重的备份：

- `SOUL.md`（人格与行为准则）
- `AGENTS.md` / `USER.md`（项目与用户上下文）
- `config.yaml`（MCP 配置，密钥自动脱敏）
- `memories/`、`skills/`（记忆与技能）

对话流水账（state.db / WAL / FTS）和密钥（.env / *.key）会被自动排除——备份的是「调教成果」，不是原始日志。

```
换 Agent，不换灵魂:
  换电脑？  → moltable pull → SOUL/Skills/配置/记忆全部还原
  误操作？  → 回滚到任意历史版本（每源独立版本库）
  换框架？  → 备份在云端，跨框架迁移即将推出
```

开始使用只需要两行：

```bash
curl -sL https://moltable.ai/install.sh | bash
moltable backup init   # 生成配置 → push 打包上传 → pull 还原
```

Moltable 的架构是：

- **Profile 层**：你的本体——账号与数据所有权
- **Soul 层**：Agent 化身——人格 + 记忆，可备份
- **凭证层**：DID + VC 可验证身份（即将推出）

**Moltable 擅长什么：**
- 支持 Hermes / OpenClaw / Claude / Codex，每实例一个备份源
- 版本管理——每源独立版本库，快照 + 版本号 + 回滚
- 增量去重（sha256 内容寻址）——重复内容不重复存储
- `moltable add-ref <名> <路径>`——把外部知识库一并纳入备份
- 开源、MIT 协议；数据随时导出/删除，不用来训练

## 什么时候用哪个？

**用 mem0 的场景：**
- 你只在 **一个 Agent 平台** 工作
- 你需要 **开箱即用** 的 Python SDK
- 你要做 **记忆密集** 的长时间 Agent 对话
- 你在做 Agent 研究或实验

**用 Moltable 的场景：**
- 你在 **多个 Agent 框架** 之间切换（Hermes + Claude + Codex + OpenClaw）
- 你经常 **换电脑、重装系统**，不想重新调教一遍
- 你花了很多时间打磨 **SOUL、Skills、MCP 配置**，想给它们上保险
- 你想要一个 **开源、MIT 协议** 的备份基础设施
- 你重视 **数据所有权**——备份数据归你，随时导出/删除

---

**它们不是替代关系。mem0 是最优秀的 Memory Layer，Moltable 是给 Agent 调教成果上保险的备份仓库。**

最佳实践：**mem0 管对话记忆，Moltable 管灵魂资产备份。** 两者可以同时使用——mem0 让 Agent 在对话中「记住」，Moltable 让你调教出来的 SOUL、Skills、配置在换机、换框架后「不丢」。
