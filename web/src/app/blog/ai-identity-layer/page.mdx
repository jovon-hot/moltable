2025-2026 年，AI Memory 赛道出现了至少 10 个开源项目：mem0 (58K⭐)、Engram (4.4K⭐)、Nocturne (1.2K⭐)、Wax、Stash、Mnemon……它们都在做同一件事：让 AI 记住更多。

但"记住更多"是否真的解决了用户的核心问题？

## Memory 的问题

记忆系统有两个根本性的局限：

- **记忆是碎片化的**：100 条偏好、50 条事实、200 条决策——它们之间没有层级关系。Agent 无法区分"用户喜欢表格"和"用户是 FOST 集团的 CEO"哪个更重要。
- **记忆是被动的**：Agent 需要先 search 才能获取记忆。如果 Agent 不知道要搜什么，记忆就形同虚设。

这就像给了你一个无限容量的硬盘，但没有文件系统。数据都在，但你找不到。

## 三层架构：Profile → Soul → 凭证

这是 Moltable 最核心的设计决策——把「用户本体」和「可备份的 Agent 化身」分开：

- **Profile（本体）**：你本人。唯一、不可复制。拥有所有数据的所有权。
- **Soul（化身）**：人格 + 记忆，可备份。你可以为不同场景维护多个化身（战略顾问、保守审核员、创意伙伴），每个化身是一个独立的备份源，输出风格完全不同。
- **凭证（DID + VC）**：可验证身份，即将推出。

这个架构的关键洞察是：同一个人的 Profile 是稳定的，但面对不同场景需要不同的化身。做战略决策时需要激进的分析师，审核合同时需要保守的审核员。两个化身各自独立备份——就像同一个人的左右脑，各有各的档案。Hermes、OpenClaw、Claude、Codex 每实例一个备份源，互不干扰。

## 为什么竞品不做

不是想不到，而是定位决定的。mem0 定位"通用记忆层"——适合任何 AI 应用插入记忆功能。这个定位天然偏向运行时组件，无法回答"你的 Agent 丢了怎么办"。

Moltable 定位"灵魂资产版本仓库"——只服务 AI Agent 和 AI 重度用户。这个窄定位允许我们做深：bundle + manifest + CAS 内容寻址去重 + 对象存储；每个备份源独立版本库，快照 + 版本号 + 回滚；sha256 增量去重；add-ref 引用外部知识库一并备份。开源 MIT，MCP 接入走 HTTP（https://api.moltable.ai/mcp + X-API-Key），不需要本地拉起服务。
