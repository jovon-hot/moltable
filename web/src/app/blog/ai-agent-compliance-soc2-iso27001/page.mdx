# AI Agent 合规进阶：SOC2 / ISO27001 与数据跨境清单

**你的客户（一家做欧洲业务的企业）在采购评审里甩过来三样东西：一份 SOC 2 Type II 报告、一张 ISO 27001 证书复印件，还有一个问题——「我们的记忆数据要存放在 EU 境内，你们的跨境合规怎么做的？」** 如果你答不上来，合同就凉了。

上一篇 [AI Agent 记忆的数据主权：GDPR 实操与自托管合规清单](/blog/ai-memory-data-sovereignty-gdpr) 解决的是「个人权利」：删除权、数据可携带、审计日志怎么落地。这一篇解决的是「组织信任」：当客户是企业而不是个人，合规问题就从「你能不能删」升级成「你的体系可不可信、数据能不能出境」。

两篇合起来，才是 2026 年企业级 Agent 记忆层的完整合规拼图。

---

## 一、GDPR 是底线，SOC2 / ISO27001 是门票

先把概念摆正：GDPR、SOC 2、ISO 27001 是三种不同的东西，不是同一件事的三个叫法。

| | GDPR | SOC 2 | ISO/IEC 27001 |
|---|---|---|---|
| 性质 | 法律（欧盟条例） | 审计报告（AICPA 框架） | 认证（国际标准） |
| 管什么 | 个人数据权利 | 服务商控制的设计与运行有效性 | 信息安全管理体系（ISMS） |
| 谁管 | 监管机构（DPA） | 独立 CPA 审计师 | 第三方认证机构 |
| 是否强制 | 面向欧洲用户是 | 企业采购普遍要求 | 企业采购普遍要求 |
| 周期 | 持续 | Type I 时点 / Type II 6-12 个月运行观察 | 证书 3 年 + 年度监督审核 |

GDPR 问你「删不删得掉」；SOC 2 问你「你声称的控制是不是真的在运行」；ISO 27001 问你「你有没有一套持续改进的安全管理体系」。

对企业客户来说，**GDPR 是法律底线，SOC 2 / ISO 27001 是采购门票**——2026 年欧洲企业做供应商尽调，没有 SOC 2 Type II 报告或 ISO 27001 证书，很多时候直接进不了备选名单。做 Agent 记忆层、自托管部署、企业级产品的团队，这是绕不开的功课。

## 二、SOC 2：五项信任服务原则怎么落到记忆层

SOC 2 基于 AICPA 的 Trust Services Criteria（TSC）。**Security（安全）是所有 SOC 2 报告的必选原则**，其余四项——Availability（可用性）、Processing Integrity（处理完整性）、Confidentiality（保密性）、Privacy（隐私）——按业务范围选择。Type II 要求在 6-12 个月的观察期后由独立审计师出具报告，证明控制「不仅设计合理，而且真实运行」。

对 Agent 记忆层，五项原则的工程落点：

### 2.1 Security（必选）：记忆即资产，资产即攻击面

- **访问控制（CC6）**：记忆数据按 `identity_id` 做行级隔离，API 密钥分权（读/写/管理），管理端强制 MFA
- **变更管理（CC8）**：记忆 schema 变更走审批，备份还原演练定期做
- **风险管理（CC3）**：自托管场景下，客户评估的不是你的云，而是你的打包产物——最小化镜像、无秘密硬编码、依赖锁定

### 2.2 Availability：记忆层的「可用性」承诺写进 SLA

记忆层是 Agent 的「长期记忆」，丢不起。备份策略（3-2-1）、恢复时间目标（RTO）与恢复点目标（RPO）要量化：例如 RPO ≤ 15 分钟（增量备份），RTO ≤ 1 小时（自动化还原脚本 + 演练记录）。

### 2.3 Processing Integrity：处理完整性 = 记忆不被悄悄改坏

- 输入校验与一致性校验：写入记忆库的事实先过校验再落库
- 版本化：每次记忆变更留快照，可哈希校验、可回滚（文件级打包 + manifest + CAS 存储天然满足这一条）
- 审计日志：谁在什么时候写了什么记忆，可追溯

### 2.4 Confidentiality & Privacy：加密与数据最小化

- 传输 TLS 1.3，静态 AES-256，密钥进 KMS/HSM 而非环境变量
- Privacy 原则本质是 GDPR 的映射：告知、选择、删除、可携带——正是上一篇 [GDPR 实操](/blog/ai-memory-data-sovereignty-gdpr) 覆盖的内容

## 三、ISO 27001：93 项 Annex A 控制，先映射再补课

ISO/IEC 27001:2022 的 Annex A 共 **93 项控制**，分四组：组织控制（A.5，37 项）、人员控制（A.6，8 项）、物理控制（A.7，14 项）、技术控制（A.8，34 项）。做认证的第一步不是「全做」，而是 **SoA（适用性声明）**：逐项判断「适用 / 不适用 / 采用何种措施」，不适用要给出理由。

Agent 记忆层团队最该先对齐的高价值控制项：

| 控制项 | 内容 | 记忆层的对应动作 |
|---|---|---|
| A.5.1 | 信息安全政策 | 安全政策文档化，覆盖记忆数据生命周期 |
| A.5.9 | 资产清单 | 登记所有存储资产：Postgres、向量库、图谱、文件快照、备份 |
| A.5.10 / A.5.11 | 信息分类 / 标签 | 记忆按敏感级别打标（身份 / 偏好 / 机密） |
| A.5.19 / A.5.21 | 供应商与 ICT 供应链安全 | 自托管分发物：SBOM、镜像签名、依赖审计 |
| A.8.2 | 特权访问 | 管理端 MFA + 最小特权，特权操作留痕 |
| A.8.5 | 安全鉴别 | 密钥轮换、会话管理、账号生命周期 |
| A.8.9 / A.8.10 | 配置管理 / 信息删除 | 基础设施即代码 + 级联删除（承接 GDPR 删除权） |
| A.8.15 / A.8.16 | 日志与监控 | 审计日志防篡改、告警阈值、保留策略 |
| A.8.24 | 密码学 | 加密策略统一、密钥生命周期（生成/轮换/销毁） |
| A.8.28 | 安全编码 | 依赖扫描、SAST、发布前安全测试 |

不需要一上来就 93 项全齐。**先做 SoA 映射，识别与记忆数据直接相关的 15-20 项，把工程动作补上，再走认证**——这条路径比「照单全抄」省一半时间。

## 四、数据跨境：中国出境与欧盟 Schrems II 的自托管解法

这是「数据主权」最锋利的战场。客户在欧盟/中国，数据必须留在境内，你的产品架构就得支持区域化部署。

### 4.1 欧盟：Schrems II 之后的合规三件套

2020 年欧盟法院在 Schrems II 案（C-311/18）中废除了美欧 Privacy Shield，并裁定标准合同条款（SCC）依然有效，但**不能「签了就不管」**——每次向第三国传输都要做：

1. **TIA（传输影响评估）**：逐案评估接收国法律环境（如美国 FISA 702 监控权力）对数据保护水平的影响
2. **补充措施**：评估不通过时补——传输层加密、密钥留在 EU 境内、数据驻留欧盟
3. **监管备案**：复杂场景按 DPA 要求备案

2023 年欧盟通过 EU-US Data Privacy Framework 重新给了美国一个充分性认定，但**针对中国等无充分性认定的国家，SCC + TIA + 补充措施仍是标准路径**。

自托管就是最干净的补充措施：**数据不出境，就没有跨境传输**。记忆层产品如果支持「EU 境内一键部署」，等于把跨境合规问题从「法务题」降级成「部署题」。

### 4.2 中国：PIPL 出境三路径与 2024 新规

《个人信息保护法》第 38-43 条给出出境三路径：**安全评估**（网信办）、**个人信息保护认证**、**标准合同备案**。2024 年 3 月《促进和规范数据跨境流动规定》进一步放宽：

- 非关键信息基础设施运营者、未识别为重要数据、**自当年 1 月 1 日起累计向境外提供不满 10 万人个人信息（不含敏感个人信息）**的——**免安全评估、免标准合同备案**
- 涉及重要数据、或累计向境外提供 100 万人以上个人信息的，仍需走网信办安全评估

对做自托管的团队，最实用的解读：**把数据部署在境内 = 不触发跨境机制**；确需出境的，先算清楚「多少人、什么类型」再决定走哪条路。

### 4.3 自托管合规检查清单（可直接抄）

```bash
# 部署后逐项自检（示例清单）
check_tls()      # 1. TLS 1.2+ 强制，证书自动续期
check_at_rest()  # 2. 静态加密 AES-256，密钥在 KMS，不在环境变量
check_mfa()      # 3. 管理端 MFA 强制，特权操作留痕
check_backup()   # 4. 3-2-1 备份 + 还原演练记录（RPO/RTO 量化）
check_audit()    # 5. 审计日志防篡改，保留 ≥ 365 天
check_delete()   # 6. 级联删除 + 删除证明（承接 GDPR 篇）
check_region()   # 7. 数据驻留声明：所有存储在同一司法辖区
check_sbom()     # 8. 分发物 SBOM + 镜像签名（供应链）
check_logs()     # 9. 日志脱敏：不记录 API Key / 敏感记忆原文
check_access()   # 10. 最小特权 + 定期权限评审
```

- **数据在你手里**：在线同步之外，文件级备份兜底——bundle 打包 + manifest + 哈希校验，本地或自托管，数据驻留由你决定
