## 帖子 2：技术深度（LinkedIn · 长文）

Most AI memory systems today are built on one assumption: vector similarity = relevance.

It's wrong.

Here's a real example:

User: "Let's review the auth module."

Vector-only memory returns:
✅ "JWT preference" (from Project Y, 8 months ago)
✅ "OAuth is overkill" (pre-SOC2, outdated)
✅ "Supabase for auth" (irrelevant to review)

Identity Graph memory returns:
✅ "Project X uses session-based auth with Redis"
✅ "SOC2 requires MFA — audit trail needed"
✅ "Last security review flagged token rotation gap"

Same query. Same database. Completely different results.

The difference isn't the retrieval algorithm. It's the query planning:
→ Who is the user?
→ What Persona are they in?
→ Which project are they working on?
→ What's the temporal relevance window?

Vector search = semantic similarity.
Identity Graph = contextual relevance.

Full deep-dive: https://moltable.ai/blog/identity-graph-vs-vector-search
