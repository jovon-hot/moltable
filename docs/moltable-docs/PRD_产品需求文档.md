# Moltable · 产品需求文档 (PRD)

> 版本: V1.0 | 状态: 草案 | 日期: 2026-06-16

---

## 一、产品定义

### 一句话

**Moltable 是 AI 时代的身份层——在任何 AI 里加载你的 Moltable，AI 就自动认识你。**

### 三句话

1. 用户在所有 AI 中积累的偏好、记忆、决策模式，统一存储在 Moltable
2. 任何支持 MCP 的 AI Agent 连接 Moltable 后，调用一次 `auto_provision()` 即完成配置
3. 用户可以创建多个 Persona（人格）和 Agent（执行体），共享同一套 Identity 和 Memory

### 不是

- ❌ 不是又一个 AI 聊天界面
- ❌ 不是模型路由器
- ❌ 不是 Prompt 模板库

### 是

- ✅ AI 之间的用户身份中间层
- ✅ 跨平台记忆同步基础设施
- ✅ AI 人格与 Agent 的管理系统

## 二、核心用户场景

### 场景 1：跨 AI 无缝切换

```
赵在 Hermes 里工作了 3 个月，积累了大量偏好和记忆
    → 今天想试试 Claude Desktop
    → 在 Claude 里加载 Moltable Skill，输入 API Key
    → Claude 调用 auto_provision()
    → Claude 自动知道：
        - 赵是 FOST 车检集团的经营者
        - 偏好数据驱动的报告，结论先行
        - 当前项目：月度经营分析、无人车运营平台
        - 报告必须覆盖模板所有章节，数据必须真实
    → 赵直接说"帮我做 6 月经营分析"
    → Claude 带着完整上下文开始工作
```

### 场景 2：多 Persona 切换

```
赵创建了两个 Persona：
    - "战略顾问"（麦肯锡风格·数据驱动·激进）
    - "保守审核员"（风险厌恶·逐项检查·合规导向）

分析新市场时 → 切换到"战略顾问"模式
审核合同时 → 切换到"保守审核员"模式

同一个底层 AI，不同的行为模式。切换只需一个参数。
```

### 场景 3：AI 实体间的结构化碰撞

```
赵让"战略顾问"和"保守审核员"同时分析无人车项目：
    → 两个 Persona 各自基于共享的 Memory 独立分析
    → 战略顾问：市场大·快速入场·先占位
    → 保守审核员：法规风险·资金链·需 6 个月试点
    → 赵看到两种视角的碰撞，做更全面的决策
```

### 场景 4：记忆的持续积累

```
赵在 Hermes 中说"以后报告用表格不要用图表"
    → Hermes 调用 save_memory(category=preference, content="赵偏好表格而非图表")
    ↓
第二天，赵在 Claude Desktop 中要求生成报告
    → Claude 调 auto_provision() → 读到这条偏好
    → Claude 自动输出表格格式
    ↓
赵不需要再说第二遍。所有 AI 自动同步。
```

## 三、三层架构

```
┌──────────────────────────────────────────┐
│              Identity（唯一）             │
│  用户本人 · 不可复制 · 拥有所有数据        │
│  Jovon · jovon@email.com                │
└────────────────┬─────────────────────────┘
                 │ 拥有
    ┌────────────┼────────────┐
    │            │            │
┌───▼───┐  ┌────▼────┐  ┌───▼───┐
│Persona│  │ Persona │  │Persona│  人格层（多个）
│战略顾问│  │保守审核员│  │产品经理│  共享 Memory
│       │  │        │  │       │  行为模式不同
└───┬───┘  └────┬────┘  └───┬───┘
    │           │           │
    │     ┌─────▼─────┐     │
    │     │   Agent   │     │     执行层（多个）
    │     │ PPT生成器  │     │     纯执行
    │     └───────────┘     │     不拥有人格
    │                       │
```

### 三层定义

| 层 | 数量 | 拥有什么 | 示例 |
|----|------|---------|------|
| Identity | 1 | 用户账户、API Key、所有数据的所有权 | Jovon |
| Persona | N | 行为模式、思维风格、专业领域 | 战略顾问、保守审核员 |
| Agent | N | 工具调用能力、执行任务 | PPT生成器、数据分析器 |

## 五、非功能需求

| 需求 | 标准 |
|------|------|
| 响应时间 | MCP API < 500ms (P99) |
| 可用性 | 99.5% |
| 安全 | API Key 可随时吊销；记忆加密存储；TLS 1.3 |
| 隐私 | 用户可随时导出/删除全部数据 |
| 扩展性 | 支持 10 万用户，1000 万条记忆 |

---

## 六、不做的事（明确边界）

- ❌ 不做 AI 模型训练
- ❌ 不做 AI 对话界面
- ❌ 不做 Prompt 模板市场
- ❌ 不替代任何 AI 产品
- ❌ 不做 Agent 运行时（不执行任务，只管身份和记忆）
