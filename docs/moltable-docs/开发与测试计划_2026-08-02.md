
### 1.2 邮箱验证

**用户故事:** 注册时必须验证邮箱，防止批量虚假注册。

**后端改动:**

```python
# server/routes/auth.py — register 流程改为两步

# Step 1: POST /api/auth/register → 发送验证码
Request: {"email": "...", "password": "..."}
Response: {"message": "验证码已发送到邮箱（5分钟有效）"}

# Step 2: POST /api/auth/verify → 验证码确认
Request: {"email": "...", "code": "123456"}
Response: {"api_key": "molt_xxx...", "sync_code": "molt_sync_xxx..."}
```

验证码存储: 内存 dict（`{email: (code, expires_at)}`），5 分钟过期。发送: `smtplib` 或调用 SendGrid/Mailgun API。

**Agent 自助注册路径不受影响:** Agent 注册走 `POST /api/auth/sync`（同步码找回），不需要邮箱验证。

**测试:**
```bash
# 1. 注册 → 验证码已发送
curl -s -X POST $API/api/auth/register -d '{"email":"test@x.com","password":"Test2024!"}'

# 2. 不带验证码 → 拒绝
curl -s -X POST $API/api/auth/verify -d '{"email":"test@x.com","password":"Test2024!"}'
# → {"error": "验证码已发送，请查收邮件"}

# 3. 正确验证码 → 成功
curl -s -X POST $API/api/auth/verify -d '{"email":"test@x.com","code":"123456"}'
# → {"api_key": "molt_xxx..."}
```

## 五、Sprint 3 — 生态 + 评测（8月13-19日）

### 3.1 Moltable 专属评估基准

设计三个维度的基准：

**1. Cross-Agent Recall (跨 Agent 记忆召回)**

```
测试流程:
  1. Agent A 写入 20 条不同类别的记忆
  2. Agent B 用 auto_provision 加载
  3. 对每条记忆生成语义查询
  4. 检查 recall@k (k=1,3,5)
  5. 检查 MRR (Mean Reciprocal Rank)

指标: recall@1 ≥ 90%, MRR ≥ 0.85
```

**2. Persona Fidelity (Persona 忠诚度)**

```
测试流程:
  1. 创建 Persona "数据极客"（system_prompt: "你热爱数据，每次回答必须引用至少3个数字"）
  2. 用该 Persona 回答 10 个问题
  3. LLM-as-judge 评分: 是否每次引用了数字？是否体现了数据热爱？
  
指标: 人工评分 ≥ 4.0/5.0, LLM-judge 一致性 > 85%
```

**3. Provision Completeness (上下文加载完整性)**

```
测试流程:
  1. 创建: 1个用户 + 10条偏好 + 3个Persona + 2个项目 + 5条决策
  2. auto_provision() 
  3. 检查: preferences=10, personas=3, projects=2, core_knowledge≥5

指标: 完整性 = 返回项数/应有项数 ≥ 95%
```

**实施:** 新建 `benchmarks/` 目录，脚本化三个基准。结果写入 `BENCHMARKS.md`，公开展示在 `/research` 页面。

**测试:** 在干净测试账号上跑完三个基准 → 得分全部达标 → 提交 `BENCHMARKS.md`。
